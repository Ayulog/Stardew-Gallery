# 星露谷画廊需求说明

> 状态：v1 定稿，2026-10-21，适用于 2.10.0 起的版本。
>
> 依据：1.0.0 的最初定位、2.0–2.9 的版本记录，以及 2026-10-21 用户确认的取舍（见第 8 节）。
>
> 本文是当前需求的唯一依据。`docs/` 中的阶段文档、版本说明和调研只保留为历史记录，不再作为范围或承诺。

## 1. 定位

**星露谷画廊是一本游戏内的好感剧情相册。** 它做三件事：

- 按角色收集当前生效的好感剧情。
- 告诉玩家还差哪些条件。
- 在不影响存档的前提下，让玩家重温看过的剧情。

这与 1.0.0 公测版的定位一致：把当前游戏和已装 Mod 中生效的好感事件整理成相册，并在单人存档中安全回放。事件查询、来源显示、剧照、自定义名称都服务于这个定位，不另立目标。

## 2. 使用场景

| 场景 | 玩家想做的事 | 对应功能 |
| --- | --- | --- |
| 重温 | 再看一遍喜欢的好感剧情，包括扩展 Mod 的剧情 | 相册、安全回放、倍速 |
| 补全 | 某段剧情为什么还没触发、还差什么、前置是哪个 | 条件说明、前置跳转、事件查询 |
| 查问题 | 某段剧情来自哪个 Mod、定义在哪个文件，方便排查整合包 | 事件来源 |
| 纪念 | 给喜欢的剧情拍照当封面、起名字 | 剧照与封面、自定义名称 |

## 3. 设计原则（硬性约束）

1. **存档安全第一。** 画廊的任何操作都不能改变真实进度，回放也不能。做不到时，宁可不回放或不切换演出环境。
2. **只读分析。** 条件和来源分析都是只读的：
   - 不执行触发器动作。
   - 不调用第三方条件。
   - 不改变已看状态。
   - 判断不了的标为“未知”。
   - 与游戏实际判定不一致视为缺陷。
3. **离线。** 不联网，恢复 1.0 的原则。
4. **不干预其他 Mod。**
   - 不补丁 SMAPI 或其他 Mod 的内部实现。
   - 回放期间的拦截只作用于画廊自己发起的回放。
   - 不改写游戏文件和其他 Mod 的资源。
5. **基于当前状态。** 目录和回放都使用当前存档和当前生效的内容，不做历史冻结版本。
6. **保留玩家数据。** `config.json`、`event-photos/`、`user-data/` 在升级中保留并保持兼容。
7. **可选依赖可回退。** GMCM、Portraiture、DDFC、Scale Up 缺失或出错时，基础画廊照常可用。

## 4. 功能需求

“核心”是产品存在的理由，“辅助”服务于核心。

### 4.1 好感剧情相册（核心）

- **收录**：带有明确正向好感关系条件的剧情，以及可信的续篇，归入对应角色的相册。
  - 关系条件包括心数、好感点数、约会、配偶，覆盖 GSQ 写法和多角色门槛。
  - 普通剧情和前置事件不进相册。
- **去重**：游戏原生复制到多个地点的同一剧情只出现一次，例如爷爷评价、Trailer 与 Trailer_Big。真实身份（资产 + ID）仍然保留。
- **角色**：使用当前游戏中的角色名称和外观，角色别名和分身合并为一人。
- **首页**：
  - 角色列表和角色搜索（中文界面可用拼音）。
  - “事件查询”入口。
  - “一键解锁全部 / 恢复锁定”。
- **角色页**：
  - 生日、本周送礼、今日是否对话。
  - 已看数 / 总数、关系状态。
- **剧情卡片**：名称（自定义名优先）、封面、心数门槛、已看 / 已解锁 / 锁定状态。
- **一键解锁**：
  - 只影响画廊内的查看和回放权限，绝不修改真实进度。
  - 按存档保存。联机农场工无法写存档数据，只在本次会话生效，且不报错。
- **刷新**：读档、返回标题、切换语言、事件或角色数据变化后自动更新。打开画廊不应每次都全量重建目录。

### 4.2 剧情详情与条件说明（核心）

- **显示内容**：
  - 名称、事件 ID、地点、来源（见 4.5）。
  - 封面缩略图、条件清单。
  - 可以回放时显示回放按钮。
- **条件清单**：
  - 每条写明要求和当前状态：满足、未满足或未知。
  - 未知要说明原因，例如随机结果、第三方条件、需要实时环境。
- **判定语义**：
  - 必须与游戏 1.6.15 实际判定一致，包括游戏自身的特殊行为（例如一个条件写多个季节时只检查第一个）。
  - 做不到一致时标为未知，不给出错误的满足或未满足。
- **前置跳转**：
  - 条件中引用的前置事件可点击跳转，支持多级返回原页面和原位置。
  - 要求“未看过”的否定引用不算前置依赖。
- **前置事件资料**（TriggerActions 等进度标记）：
  - 只读展示条件、获得状态、触发时机和关联剧情。
  - 不能回放。

### 4.3 安全回放（核心）

**可以回放的范围**

- **好感剧情**：已看过，或开启了一键解锁。
- **普通剧情**：GMCM 中开启“普通剧情回放”（默认关闭），且已看过或已一键解锁。
- **不可回放**：前置事件和内部流程。
- **联机限制**：只支持单人。联机和分屏下可以浏览画廊，但不能回放。
  - 分屏在游戏里属于本地联机，规则与网络联机相同。
  - 以联机方式运行的存档都不能回放，包括房主独自在线。

**存档安全（最高优先级）**

回放无论自然结束、跳过还是启动失败，结束后以下状态都必须与回放前一致：

- 位置与朝向、时间。
- 金钱与收入统计、成就。
- 好感、已看事件、邮件、任务、对话标记、配方、技能经验。
- 背包物品的完整属性，包括鱼竿上的鱼饵和钓具、弹弓弹药。
- Buff、已听歌曲、已访问地点。
- 地图上的作物、肥料、果实和采集物。

其他要求：

- 回放期间禁止保存。
- 回放前自动备份存档，备份位置和保留数量写进 README。
- 回放过程中不得启动或结束真实节日、真实事件。
- 回放结束后自动触发的后续事件要拦下，并且不标记为已看。

**演出**

- 按事件条件临时设置时间和天气。
- 季节只改变演出画面，不得触发全局换季效果（例如清空果实、删除肥料）。
- 倍速 1x / 2x / 4x，可用快捷键或屏幕按钮切换。
- 对话自动推进只在 2x / 4x 生效，遇到选项会停下等玩家选择。

**可靠性**

- 超时按游戏实际推进计算。窗口失焦导致游戏暂停时，不得判定为超时。
- 失败保护：
  - 只有恢复玩家状态本身失败时，才退回最近一次睡觉存档。
  - 其他启动或演出失败按正常恢复流程处理并提示。
  - 提示文案与实际触发范围一致。
- 新存档在第一次睡觉前没有存档文件，要给出明确说明，不能只给笼统的失败提示。

**如实告知的边界**：第三方自定义事件命令对外部文件或私有状态的修改，无法回滚。

### 4.4 事件查询（辅助）

- **范围**：好感剧情、普通剧情、前置事件。内部流程不展示。
- **搜索**：自定义名称、原名、事件 ID、角色、地点、来源 Mod 的名称或 ID。游戏语言为中文时，名称、地点和角色也能用拼音（全拼、首字母或混合）找到。
- **筛选**：类型、角色、地点、来源、完成进度（已看 / 未看）。
- **相对 2.9.0 移除**：条件满足状态、季节、天气、时间、心数筛选。条件统一在详情页查看。
- **统计**：查询结果不计入相册收藏统计。

### 4.5 事件来源（辅助，用于查问题）

- **显示内容**：详情页显示事件的原始提供者。
  - 原版，或 Mod 的名称、ID、版本和定义文件。
  - 有多个候选时全部列出。
  - 证据不完整时明确提示，例如原包扫描失败、只找到覆盖包。
- **其他声明者**：同时列出也在文件中声明了这个事件的其他 Mod（覆盖或改写者），方便排查冲突。
  - 这些是静态声明，注明“不一定在当前存档生效”。
  - 不做运行时修改追踪，不补丁 SMAPI 内部实现。
- **识别范围**：
  - 支持 Content Patcher（含 Include / FromFile 和配置令牌）、AliveNpcs 和原版。
  - 其他框架和纯 C# 事件显示“未知”，不靠推测给出来源。
- **跨平台**：Windows、Linux（Steam Deck）、macOS 下结果一致。
  - Mod 文件引用的大小写与磁盘不一致时能识别，因为 SMAPI 本身不区分大小写。
  - 通过 Stardrop 等工具以链接目录部署的模组能识别。
- **用途限制**：来源只用于显示和查询，不影响收录、解锁和回放。
- **离线、只读**：不联网，不改写游戏或其他 Mod 的资源。

### 4.6 剧照与封面（辅助）

- **抓拍**：回放中通过快捷键（默认 F8 / LB）或相机按钮抓拍。
  - 画面不含 HUD、对话框和跳过按钮。
  - 任何缩放比例（包括默认 100%）下都要有效。分屏属于联机，不能回放，所以不涉及抓拍。
- **保存与管理**：
  - 照片按存档分别保存，第一张自动成为封面。
  - 可设为封面、恢复默认、移除（移入归档，不直接删除）。
- **失败处理**：写入失败要提示，并且不留下无主文件。

### 4.7 自定义事件名称（辅助）

- 按事件身份（资产 + ID）保存，本机所有存档共用。
- 相册、详情、查询中的显示与搜索保持同步。
- 原子写入。文件损坏时自动回退到最近的备份，备份数量有上限。

### 4.8 相册外观兼容（辅助）

- 首页和相册显示角色当前生效的肖像与小人。
- 兼容 Portraiture、DDFC、Scale Up 已核查的格式。
- 读取失败时先回退到普通肖像，最后才用占位图。日志限频。
- 只负责画廊页面。回放画面里的角色外观由游戏和已装的美化 Mod 决定，画廊不干预。

### 4.9 操作、界面与语言

- **入口**：快捷键（默认 G），或游戏菜单“收藏”页侧边的画廊按钮。README 要如实描述位置。
- **手柄与键鼠同等可用**，包括 Steam Deck：
  - 所有页面都能用方向键 / 摇杆移动焦点。A 确认，B 返回上一级，Y 打开筛选，肩键翻页。
  - “吸附菜单”开或关时，A 都作用于当前所指的项，一次按键只执行一次操作。
  - 在键鼠和手柄之间来回切换时不报错、焦点不丢。
  - 用手柄进入输入框时弹出屏幕键盘，支持中英文输入：Steam Deck 和 Steam 大屏幕模式下用 Steam 键盘（可输入中文）；其他情况用游戏自带键盘（只有英文字母），中文名称靠拼音搜索找到。其他语言的输入暂不处理。
  - 在搜索框按回车（或屏幕键盘的确定）只列出候选，不直接进入结果。
  - 在画廊输入框里用键盘打字时，按键不触发游戏和其他 Mod 的快捷键；结束输入的那次按键（回车、Esc）也不会再作用于页面。用游戏自带的方式实现，不补丁 SMAPI。
  - 摇杆、方向键和按键的跟手程度与游戏原生菜单相当。
  - 在筛选、改名等工具页按 Y / Start，返回上一级而不是关闭整个画廊。
- **语言与适配**：
  - 支持游戏官方的 12 种语言。
  - 适配不同分辨率和 UI 缩放。
  - 长文本省略显示，悬停或聚焦时可看全文。

## 5. 明确不做

- **AI Mod Exclusion 名单**，以及任何按名单或来源隐藏、限制内容的功能。
- **围绕“排除内容”的调研方向**（09-21、10-15 两份调研，见 `docs/archive/REPLAY_VANILLA_APPEARANCE_RESEARCH.md`、`docs/archive/EVENT_GALLERY_FEASIBILITY_RESEARCH_2026-10-15.md`）：
  - 回放时使用原版角色外观。
  - 选择回放用的美化 Mod。
  - 按 Mod 选择收录范围。
  - Gallery Profile 与重启切换模组。
- **回放形态**：
  - 联机回放。
  - 历史版本回放。
  - 对条件未满足的剧情做“预览”（临时注入状态）。
- **收录范围**：节日主流程、婚礼仪式、夜间 FarmEvent、电影放映、纯 C# 自定义事件。
- **规划类功能**：条件求解、路线规划。
- **以后再议**（当前不在范围内）：
  - fork / switchEvent 分支剧情的来源。
  - TriggerActions 前置标记的提供者。

## 6. 兼容与质量要求

- **版本**：游戏 1.6.15+、SMAPI 4.5.2+、目标框架 net6.0。
- **平台**：Windows、Linux / Steam Deck、macOS。
- **性能**：
  - 大型整合包（约 1,000 个事件）下打开画廊没有明显卡顿。
  - 目录和来源扫描结果缓存，只在内容确实变化时重建。
- **自动验证**：
  - Checks 和 PersistenceChecks。
  - 回放状态运行时检查覆盖背包附件、季节切换、失焦计时。
  - 手柄检查覆盖所有页面、两种吸附模式和输入方式切换。
  - 截图检查覆盖 100% 与非 100% 缩放。
- **实机验收**（每次发布前，按清单进行）：
  - 回放：自然结束、跳过、启动失败、恢复异常。
  - 截图。
  - 手柄（Steam Deck 或等效设置）。
  - 12 种语言下的长文本。

## 8. 已确认的取舍（2026-10-21）

1. **运行时修改追踪：移除。** 它靠补丁 SMAPI 内部实现运作，只在 SMAPI 4.5.2.0 上生效。排查冲突改由详情页列出“同样声明了这个事件的其他 Mod”。
2. **来源筛选与按 Mod 搜索：保留**，用于查问题。
3. **联机农场工的一键解锁：只在本次会话生效**，不读写存档数据，也不报错。
4. **版本号：下一版为 2.10.0。**
5. **多人联机：保持只浏览。** 分屏同样只浏览；房主独自在线时也不开放回放。（2026-10-21 补充确认）
