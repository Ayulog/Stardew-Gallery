# 2.5.0 剧情画廊：开发包实测

本包从正式2.4.0重新实现，按已确认的好感剧情收藏＋自助查询目标开发；不是已废弃的全事件目录包。自动/隔离验证已完成部分见开发文档，以下真实存档步骤尚待验收，不正式发布。

1. **主相册**：原入口和一键解锁保留；主相册只显示好感剧情。比如Kent登门介绍应在普通查询里；Krobus无对白好感演出仍可进入相册；Scarlett.ThemeAdded等标记不列出。
2. **自助查询**：点击首页“事件查询”，分别按ID、NPC、含空格的地点名查询；全部/好感/普通筛选有效。相同ID不同资产显示精确来源，结果条数不是独立剧情数。内部流程即使输入准确ID也不作为事件结果出现。
3. **前置说明**：从相册打开详情，点击完整剧情前置，再返回。若前置为内部解锁步骤，应在原条件下说明其地点/要求，没有独立卡片或回放按钮。检查从相册和查询进入同一事件的条件结果一致。
4. **回放权限**：GMCM默认关闭普通事件回放；此时一键解锁也不能播放普通剧情。开启后，已经历普通剧情可播放，未经历仍需一键解锁。关闭一键解锁恢复正常观看限制；所有内部流程始终禁止回放。
5. **恢复**：单人记录金钱、累计收入、任务、位置与时间，分别重温好感/普通剧情，测试自然结束与跳过。確認回到原状态和原页面，特殊地点实例不串位；含邮件分支的剧情应能正常走分支，真实邮件/已看/任务记录不因重温累加。
6. **照片和返回**：普通或好感回放中拍照，进照片页设置封面，再返回详情/查询/角色相册；选择、筛选、滚动和焦点保持。键鼠和手柄各试一次，中文和常用其他语言检查文本无压线。

回放会省略已覆盖的奖励及部分特殊结算；未知第三方命令、私有状态或外部操作不能保证回滚。完整特殊事件需对应Mod环境实测，发现问题时记录具体事件ID、来源、正常结束或跳过、以及SMAPI日志。查询展示的是本次打开画廊时当前可发现的内容；CP条件变化后重新打开获取新的内容快照。

不要求为每个小修重复所有步骤；反馈出现在哪个模块，就针对该模块和相邻调用验证。
